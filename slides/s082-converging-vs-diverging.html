Converging vs Diverging

CONVERGES

Query vendor history

Gap found → request docs

Docs arrive → verify

Enough context → recommend

STOP ✓

DIVERGES

Query vendor history

Ambiguous → assume complete

Recommend on thin context

Re-checks, re-doubts, re-queries

Never stops / confident-wrong

The difference is not the model. It's the loop you built around it.

The one place I let 'lean' bend, at your call. Same starting move, two loops.

Left: a stopping condition and a verification step exist — it reaches enough-context and halts.

Right: no real stopping condition, weak verification — it either spirals or locks onto a confident wrong answer and won't leave.

The punchline: the model is identical. The engineering of the loop is what separates convergence from divergence.
