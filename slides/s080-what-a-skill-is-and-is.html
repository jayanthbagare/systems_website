III · A primer

What a skill is, and is not

Systems · Constraints · Agents

Add-on · slide B1

A skill is a small, named, reusable procedure for using tools — loaded only when the agent needs it.

Prompt

An instruction the model reads once. One-shot. Not parameterised, not versioned, not testable in isolation.

“Triage this notification.”

Tool

An action the agent can take in the world. A verb — query, write, call.

query_SAP_PM(asset_id) → records

Skill

A recipe for using tools. Named, parameterised, testable. Loaded just-in-time. Composable.

score_criticality(notification) — uses 3 tools, returns 1–5 score

The architectural payoff: you stop writing one giant prompt and start composing many small, testable skills.

The comparison is the lesson. PM/EM audiences instinctively reach for 'a better prompt' when an agent misbehaves. The correct move is almost always to extract the failing behaviour into a named skill, test it in isolation, then re-compose.

Skills are what make agents engineerable. Without skills you have a black-box prompt; with skills you have a system you can reason about.
