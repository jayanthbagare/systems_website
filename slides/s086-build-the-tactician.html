Build the Tactician

Systems · Constraints · Agents

challenges/challenge_04_agent_tactician — a Work Order arrives, the pool is damaged. Produce a plan, not a report.

What you do

Decompose the behaviour into named, testable skills.

Assess the pool, read the market, plan the invite list.

Make it adapt when there are not enough healthy vendors.

What you produce

An RFQ plan for the same Work Order at month 5, month 10 and month 15.

An adaptation note for each, saying what changed and why.

How you know you're done

The three plans are meaningfully different. If they look the same, you built a ranking function.

PM writes the acceptance cases before the developers write the skill. Those cases are the eval — subsystem five — and writing them last is how agent projects quietly fail.

Devs pair per skill · PM writes evals first · EM enforces the three-scenario run

The three-scenario run is non-negotiable. A single run always looks impressive and proves nothing.

Common failure: the agent talks but never calls create_rfq_plan. Tell pods to check the loop terminates in a decision, which is the stopping condition from the loop engineering slide.

If time is short, drop month 5 and run 10 and 15 only. Keep at least two.
