V · Why

One task is not one call.

Systems · Constraints · Agents

A single-turn call

One inference. It answers, and it stops.

You can price it before you build it: tokens in, tokens out, done.

The cost is known at design time.

An agentic loop

Plans, calls a tool, reads the result, handles an exception, verifies, re-tries, continues.

Ten to twenty inferences for the same unit of work — and the number is decided by the task, not by you.

The cost is discovered at runtime.

You have already seen this distinction today, under another name.

Frozen thinking has a frozen cost. Runtime thinking has a runtime cost.

The callback to the Frozen vs Runtime slide is the point of this one. The pods already accepted that an agent moves the decision into the moment. Almost nobody notices that this moves the COST into the moment too.

If a pod objects that they can cap the calls — good, that is exactly the next slide. Tell them to hold the thought.

Worth saying plainly: this is the strongest argument for the automation altitude. If the answer is stable, freezing it also freezes the bill.
